Requirements and installation

  • Unity 6.0 or newer.
  • An Animator Controller with direct AnimationClip states.
  • For runtime Animation Events, the receiving component must be on the same GameObject as the Animator.

Install the package, allow Unity to compile, then open Tools → Animation → Animation Cue Studio. No scene component is required merely to author standard Animation Events.

BlendTree states are shown for context, but a BlendTree does not provide one unambiguous clip to edit. Open or author the individual source clip instead.

Quick start

  1. Select a scene GameObject containing an Animator.
  2. Open Animation Cue Studio and click Use Selection.
  3. Select a state in Animation States.
  4. Right-click an event track and select Add Event Here.
  5. Choose a method tagged with [AnimationCueEvent].
  6. Set its Float, Int, String or Object value when required.
  7. Click Apply Events. Until then, changes remain drafts.
  8. Run Validate Selected Animation before testing the game.

Animator toolbar

The Animator field is the source for states, clips and preview components. Use Selection assigns the selected scene Animator. Refresh rebuilds the state and event catalog after controller or script changes.

Animation States

The left panel lists controller states by layer and state-machine path. Select a state to load its direct clip, Animation Events and supported StateMachineBehaviours. Animator Override Controller clip replacements are resolved.

Animation Preview

The centre panel renders an isolated, hidden clone. Camera navigation and display toggles affect only the editor preview.

Cue Inspector

The right panel contains state behaviours, attack-window settings, duration cues, root-motion analysis, the selected event and validation commands. Foldouts keep unrelated settings collapsed.

Resizable layout

Drag the vertical panel dividers to resize Animation States, Animation Preview and Cue Inspector. Drag the timeline's upper edge to change its height. At narrow widths, the workspace switches to a stacked layout.

Preview viewport

The preview clone is evaluated manually, so scene physics and runtime Animation Events do not drive it. The Studio invokes only explicitly opted-in cue methods during preview.

Preview methods execute in Edit Mode on a hidden clone. Do not save assets, modify project data, apply damage, change inventory or call Destroy. Use DestroyImmediate for preview-owned temporary objects.

Timeline and playback

The timeline combines attack ranges, duration ranges and standard Animation Events. The playhead uses seconds while edits snap to the source clip frame rate.

  • Use playback controls to jump to the first frame, step backward, play/pause, step forward and jump to the final frame.
  • Click the ruler to scrub. Drag the playhead for continuous scrubbing.
  • Use the mouse wheel to zoom around the cursor and middle-mouse drag to pan.
  • Drag a marker to retime it. Left/Right Arrow nudges the selected event by one source frame.
  • Right-click a track to add an event at that exact time.
  • Right-click a marker to copy or delete it. Paste uses the current playhead time.
  • Right-click a track label to rename or delete custom tracks.

Tracks and colours are editor-only organisation. The function name, time and parameters are stored on the AnimationClip.

Authoring Animation Events

Expose a method

Add [AnimationCueEvent] to a method on a component used by the animated GameObject. The method name is the event name; track classification is chosen in the Studio.

using CombatAnimationAuthoring.Runtime;
using UnityEngine;

public sealed class CharacterEffects : MonoBehaviour
{
    [AnimationCueEvent]
    public void PlayFootstep()
    {
        // Your runtime audio implementation.
    }
}

Selected Event inspector

FieldMeaning
FunctionThe attributed method Unity calls.
Timeline TrackEditor-only visual classification.
FloatValue passed to a method accepting one float.
IntValue passed to a method accepting one int.
StringValue passed to a method accepting one string.
ObjectAsset or object passed to a method accepting a compatible UnityEngine.Object type.

Supported signatures are: no parameter, one float, int, string, compatible UnityEngine.Object, or AnimationEvent. This mirrors Unity's Animation Event parameter workflow.

Renaming a method does not automatically rewrite existing clips. Re-open the event, choose the renamed method and apply the clip again.

Audio and VFX preview

[AnimationCueEvent] makes a method authorable. Implementing IAnimationCuePreviewReceiver gives the Studio permission to invoke that component's tagged methods during editor playback.

public sealed class CharacterEffects :
    MonoBehaviour,
    IAnimationCuePreviewReceiver
{
    [SerializeField] AudioSource audioSource;
    [SerializeField] AudioClip footstep;
    [SerializeField] ParticleSystem impact;

    [AnimationCueEvent]
    public void PlayFootstep()
    {
        audioSource.PlayOneShot(footstep);
    }

    [AnimationCueEvent]
    public void SpawnImpact()
    {
        Instantiate(impact, transform.position, transform.rotation);
    }
}

The interface contains no methods and performs no playback itself. Your attributed method can call Unity Audio, FMOD, Wwise, a pool, or another project-owned service.

  • Keep preview methods cosmetic, deterministic and safe outside play mode.
  • For one-shot VFX, use the socket as the spawn transform but do not parent the instance unless it should follow the socket.
  • Stop or replace preview audio when replaying the same cue; do not start an entire random-resource container repeatedly.
  • Runtime-only events can still be authored. Omit IAnimationCuePreviewReceiver when preview execution is unsafe.

Optional direct-asset player

AnimationCuePlayer provides package-owned direct playback methods for simple AudioClip/AudioResource and particle-prefab events. It is optional; custom middleware does not need it.

Attack windows

An attack window is the normalized time range during which one or more hitbox slots are active. It is stored in AnimationCueAttackWindowSmb on the Animator state rather than as two unrelated Animation Events.

Add and edit an attack window

  1. Select the attack state.
  2. Open State Behaviours in Cue Inspector.
  3. Click Add beside Attack Window.
  4. Select the active hitbox slot mask.
  5. Drag the range edges on the Attack Window track or edit Window Start and Window End.
  6. Implement IAnimationCueAttackWindowReceiver on a component beside the Animator.
public sealed class AttackWindowHub :
    MonoBehaviour,
    IAnimationCueAttackWindowReceiver
{
    public void OpenAttackWindow(int slotMask)
    {
        // Enable the matching project-owned damage hitboxes.
    }

    public void CloseAttackWindow(int slotMask)
    {
        // Disable the matching hitboxes.
    }
}

The built-in slot flags are Primary, Secondary, Body, LeftLeg, RightLeg, Head and Area. Projects decide what each slot controls.

Preview hitboxes

Implement IAnimationCueHitboxPreview or use AnimationCueHitbox to expose collider geometry to the isolated viewport. This is visualisation only and does not perform damage.

Duration cues

A duration cue stays active between normalized start and end times. One CombatAnimationDurationSmb stores all duration ranges for a state and notifies same-root ICombatAnimationDurationReceiver components.

Add a duration timeline

  1. Select the Animator state.
  2. Open State Behaviours.
  3. Add Duration Timeline.
  4. Add a built-in Root Motion Scale or Rotation Lock range, or add a custom duration entry.
  5. Set the ID, start/end time and optional parameters.
  6. Implement a receiver that handles only IDs owned by your project.
public void OpenAnimationDuration(
    in CombatAnimationEventData eventData)
{
    if (eventData.id == "Gameplay.Armour")
        armourEnabled = true;
}

public void CloseAnimationDuration(
    in CombatAnimationEventData eventData)
{
    if (eventData.id == "Gameplay.Armour")
        armourEnabled = false;
}

Ranges close on state exit and at a new animation loop. Removing the Duration Timeline SMB deletes all ranges stored on that state.

Root motion and import settings

The viewport previews imported root translation and rotation from the selected clip. It respects the clip's Root Transform Rotation, Position Y and Position XZ Bake Into Pose settings rather than deciding root motion from the filename.

Root Motion Analysis

The read-only analysis reports root curves, motion curves, average speed, apparent speed, angular speed and a summary of imported bake settings. It is diagnostic information—not a component required for ordinary root-motion preview.

Root Motion Scale and Rotation Lock

These optional duration cues require RootMotionDurationReceiver, which applies root motion through OnAnimatorMove.

Do not add RootMotionDurationReceiver when a Rigidbody controller, CharacterController, NavMeshAgent or another script already owns OnAnimatorMove. Integrate the duration values into that movement owner instead.

Validation

Validate Selected Animation checks the current state. Validate Animator checks all editable states.

  • Missing Animation Event receiver methods.
  • Events outside the clip duration.
  • Unsupported or mismatched event parameters.
  • Invalid attack-window and duration ranges.
  • Missing attack-window or hitbox receivers.
  • Missing opt-in root-motion receiver for built-in root-motion durations.

Results appear in the tool and Unity Console with the relevant object as context. Fix errors before warnings; warnings may describe intentional project-specific setups.

Imported FBX clips

FBX-embedded clips are read and written through ModelImporterClipAnimation. Applying events updates the selected clip definition and reimports the model.

  • Confirm the correct clip is selected before applying.
  • Save or commit the FBX .meta file because importer event data lives there.
  • Do not edit the same importer simultaneously in another Inspector.
  • Re-open the state after changing loop or root-transform settings in the FBX Animation tab.
The Studio does not require a Root Motion Analysis component. Root-motion preview comes from the clip and its importer settings.

Troubleshooting

The event works in the Studio but not in game

Confirm you clicked Apply Events, the receiver is on the Animator GameObject, the method name and parameter type match, and the runtime controller is playing the same clip.

The event does not preview

The component must implement IAnimationCuePreviewReceiver, the method must have [AnimationCueEvent], and the method must be present on the preview clone. Refresh after recompiling scripts.

Audio continues or repeats unexpectedly

Use a one-shot method and stop/replace editor preview audio before replaying. Do not ask a resource container to play every collected clip for one cue.

Particles do not appear

Ensure the method creates or plays a ParticleSystem in Edit Mode, its renderer is enabled, and the preview copy is not immediately destroyed. Prefer a one-shot instance at the socket position.

Particles follow the socket

Instantiate at the socket's position and rotation without passing the socket as parent. Parent only effects intended to follow the animated bone.

Destroy may not be called from Edit Mode

Preview code is running outside play mode. Use DestroyImmediate for preview-owned temporary objects, or branch cleanup using Application.isPlaying.

Root motion looks wrong or remains in place

Check the selected clip, Avatar validity and FBX Root Transform bake settings. Refresh after applying importer changes. A baked XZ or Y channel should remain in the pose rather than moving the preview root.

The character drops through the grid

The grid is visual and has no collision. If imported Position Y is not baked, vertical root motion is expected. Compare the same time and import settings in Unity's FBX preview.

Grid is missing

Set the Ground mode to Grid, frame the actor with F and ensure the camera has not been panned far from the origin.

Events overlap and are hard to select

Zoom in. Close markers use separate lanes; select by marker shape rather than only the label.

Materials change or become corrupted

The preview must use isolated, non-saving instances and must never modify shared Material or importer assets. Stop preview, reimport the affected material, then report a reproducible case with Unity version and render pipeline.

Invalid Avatar Rig Configuration

This comes from the model's Humanoid Avatar. Fix missing required bones in the model Rig tab or use a valid Generic setup. Animation Cue Studio cannot repair an invalid Avatar.

FBX changes do not persist

Apply Events, wait for reimport, and verify that the FBX .meta file is writable. Source-control locks can prevent importer changes.

State is listed but cannot be edited

The state likely uses a BlendTree or has no direct AnimationClip. Edit an individual source clip or assign a direct clip state.
